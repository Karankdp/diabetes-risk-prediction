# Diabetes Risk Prediction

A full machine learning pipeline that predicts diabetes risk from diagnostic measurements, compares
11 classification algorithms, tunes the top performers, handles class imbalance, and ships as a
live web app.

**Live demo:** _add your Streamlit Community Cloud URL here once deployed_

## What this project covers

- **Dataset:** [Pima Indians Diabetes Database](https://www.kaggle.com/datasets/uciml/pima-indians-diabetes-database)
  — 768 patients, 8 diagnostic features, target `Outcome` (0/1)
- **EDA:** class balance, hidden missing values (zeros used as placeholders), skewness, outliers,
  correlation heatmap, pairwise relationships, age/BMI-group risk breakdowns
- **Models compared:** Logistic Regression, KNN, SVM (Linear + RBF), Decision Tree, Random Forest,
  Extra Trees, Gradient Boosting, XGBoost, LightGBM, CatBoost
- **Validation:** 5-fold stratified cross-validation (mean ± std ROC-AUC) alongside the single
  train/test split, so model rankings aren't based on one lucky split
- **Tuning:** GridSearchCV on KNN, RandomizedSearchCV on XGBoost and LightGBM
- **Class imbalance handling:** baseline vs class-weighting vs SMOTE, compared on
  recall/sensitivity specifically
- **Threshold tuning:** the default 0.5 cutoff is replaced with a threshold chosen to hit a target
  sensitivity level, appropriate for a screening use case where missing a true positive is costlier
  than a false alarm
- **Evaluation:** confusion matrices, ROC-AUC curves, Precision-Recall curves,
  sensitivity/specificity comparison, feature importance, bias-variance tradeoff curve
- **Deployment:** a saved model artifact (`diabetes_model.joblib`) and a Streamlit app (`app.py`)
  where you can enter a patient's details and get a live risk prediction

## Running the notebook

Open `Diabetes_Risk_Prediction.ipynb` in Jupyter, Colab, or Kaggle Notebooks and run all cells top
to bottom. It will:
1. Load the dataset directly from a public GitHub mirror (no API key needed)
2. Run the full EDA, preprocessing, training, tuning, and evaluation pipeline
3. Write `app.py` and `diabetes_model.joblib` to the working directory

## Running the app locally

```bash
pip install -r requirements.txt
streamlit run app.py
```

Then open the local URL Streamlit prints (usually `http://localhost:8501`).

## Deploying on Streamlit Community Cloud (free, permanent link)

1. Push this repo (including `app.py`, `diabetes_model.joblib`, and `requirements.txt`) to GitHub
2. Go to [share.streamlit.io](https://share.streamlit.io) and sign in with GitHub
3. Click **"New app"**, select this repo and branch, set the main file path to `app.py`
4. Click **Deploy** — Streamlit Cloud installs `requirements.txt` automatically and gives you a
   permanent public URL (e.g. `https://your-app-name.streamlit.app`)

## Notes & limitations

- This is a portfolio/educational project, not a clinical decision-making tool. Model performance
  is bounded by a small dataset (768 rows) and known data quality issues (physiologically
  impossible zero values used as missing-value placeholders in the source data).
- The saved decision threshold favors sensitivity (catching true diabetic cases) over specificity,
  which is a deliberate choice for a screening context — see Section 9c of the notebook for the
  full threshold-tuning tradeoff analysis.
